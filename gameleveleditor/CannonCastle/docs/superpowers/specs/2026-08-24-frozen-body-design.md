# 冰冻体玩法设计规格

## 目标

在关卡编辑器和正式试玩中加入“冰冻体”。关卡设计者可以把一个或多个彼此接触的普通或特殊物件封装为一个有质量的复合刚体。冰冻体承受两次有效炮弹命中后破裂，随后释放内部物件，使关卡获得新的弱点、延迟坍塌和连锁破坏玩法。

## 玩家规则

- 冰冻体初始耐久固定为 2 点。
- 只有达到冰冻体有效命中速度阈值的炮弹碰撞才扣除 1 点耐久。
- 第一次有效命中后冰层继续参与物理碰撞，并显示明显裂纹。
- 第二次有效命中后冰层消失，不再参与碰撞，内部物件恢复为独立刚体。
- 冰冻体破裂前，炮弹及其他场景物件只与冰冻体的复合碰撞轮廓发生碰撞，不会直接命中、破坏或引爆内部物件。
- 冰冻体可以受力移动和旋转。其总质量严格等于内部物件质量之和，不额外计算冰层质量。
- 冰冻体破裂时，每个内部物件继承复合刚体的线速度和角速度。物件质心还要获得由刚体角速度和自身相对质心位置产生的切向速度，避免旋转中的冰冻体破裂后出现不真实的静止或同速运动。
- 冰冻体跌出有效场景边界后，按现有目标清除规则处理其内部物件；不能因不可见的内部物件阻止通关。
- 爆炸冲量可以推动冰冻体，但爆炸伤害不越过冰层直接伤害或引爆内部物件。若爆炸系统产生的有效炮弹式伤害命中冰层，则按一次有效命中处理；同一次爆炸不能重复扣除同一冰冻体多点耐久。

## 物理模型

### 复合刚体

每个冰冻体创建一个动态刚体，以所有成员物件的质量加权质心作为刚体原点。每个成员的原始形状以局部坐标和局部角度创建为该刚体上的一个或多个 fixture。这样碰撞轮廓贴合实际物件，不生成外包矩形的空气墙。

各 fixture 在冰冻阶段使用统一的冰冻碰撞身份，使伤害系统只能看到冰冻体，而不能看到成员材质。复合刚体的质量由成员目标质量按比例分配到 fixture 密度，最终质量应在浮点容差内等于成员质量总和。

### 冰冻物理参数

以下参数属于 `全局配置.json`，修改后适用于所有关卡：

- `friction`：冰冻体摩擦系数，默认 `0.1`。
- `restitution`：冰冻体弹性系数，默认 `0.2`。
- `hitSpeedThreshold`：有效命中速度阈值，默认 `5 m/s`。

耐久固定为 2，不在单关或全局面板中开放修改。全局参数必须通过既有范围校验、保存、导出和导入流程。

### 破裂与状态转换

冰冻控制器监听伤害/碰撞事件并维护 `intact -> cracked -> released` 状态。释放过程必须在安全的物理步骤边界执行：记录复合刚体位置、角度、线速度和角速度，移除复合刚体，以当前世界变换重建成员刚体，并设置继承后的速度。释放只执行一次，且不能同时留下冰冻 fixture 与成员 fixture。

内部木材、玻璃和爆炸桶在释放时保持原有耐久及未触发状态。冰冻阶段的命中不得预先消耗内部物件耐久。

## 关卡数据格式

正式关卡文档继续使用 `{ version: 2, type: "level", levelId, level }`。在 `level` 中新增可选数组：

```json
{
  "frozenBodies": [
    {
      "id": "frozen-1",
      "memberIds": ["rectangle-1", "rectangle-2"]
    }
  ]
}
```

约束：

- `id` 必须是关卡内唯一、非空字符串。
- `memberIds` 必须是非空、无重复的物件 ID 数组。
- 每个成员 ID 必须存在于同一关卡的 `castle` 中。
- 一个物件最多属于一个冰冻体。
- 冰冻体成员必须构成单一接触连通分量；允许边接触或角接触，使用小的编辑器浮点容差判断。
- 固定螺栓物件不能加入冰冻体，因为固定约束与动态复合刚体冲突。
- 旧关卡没有 `frozenBodies` 时按空数组处理，保存未使用冰冻体的旧关卡时不强制写入空字段。
- 导入、导出、复制关卡、模板、撤销/重做和未知扩展字段保留机制不得丢失有效冰冻数据。

模板保存成员物件时也保存模板内部的冰冻分组。调用模板后为冰冻体和成员生成新的 ID，并重写 `memberIds`，避免多次调用模板时交叉引用。

## 编辑器交互

- 在物品检查区域增加“创建冰冻体”和“解除冰冻体”操作。
- 选中一个或多个未冰冻物件时，如果它们相邻连通且不含固定螺栓，可创建一个冰冻体。
- 选中同一冰冻体中的任意成员时，画布默认选中整个冰冻体；拖动、旋转、复制和删除均以整个冰冻体为单位。
- Shift 多选可同时选中多个完整冰冻体和普通物件，但不能只移动冰冻体的部分成员。
- 复制冰冻体时复制全部成员，生成新的成员 ID 和冰冻体 ID，复制结果默认整体选中，并沿用现有防重叠偏移规则。
- 删除冰冻体选择时删除冰冻体及全部成员；“解除冰冻体”仅移除分组，保留成员物件。
- 如果成员位置被导入数据或其他操作改成不连通，实时检查显示具体冰冻体 ID 和断开成员；保存时阻止落盘。
- 编辑视图以浅蓝半透明冰层覆盖成员轮廓；完整状态不显示裂纹。试玩中第一次命中后显示明显白色裂纹，第二次命中播放通用冰屑破裂效果。

## 渲染

冰层按每个成员的真实形状绘制，并对相邻轮廓做视觉连接，不改变物理 fixture。内部正式材质素材仍可见，但增加冷色偏色、半透明高光和冰边。裂纹作为冰冻体级覆盖层绘制，方向由首次有效命中点向周围扩散。

缩略图和 XLSX 关卡总览显示完整冰冻外观，不显示裂纹。素材加载失败时使用同样可辨识的矢量冰层回退。

## 架构边界

- 新建独立的冰冻数据/验证模块，负责分组、ID 重写、连通性和关卡格式检查。
- 新建冰冻物理控制器，作为 `original-runtime-adapter.js` 的扩展层接管复合刚体创建、命中和释放，不修改已固化并带哈希保护的 `meteor-original-runtime.js`。
- 编辑器存储层负责原子更新 `castle` 与 `frozenBodies`，避免只有一侧写入成功。
- 渲染器只消费快照中的冰冻状态，不自行推断物理状态。
- 正式关卡 JSON 只保存分组关系；质量、摩擦、弹性、耐久和阈值不在每关重复保存。

## 错误处理与兼容性

- 无效冰冻配置在加载、导入和保存时返回带路径的错误，例如 `frozenBodies.frozen-1.memberIds.rectangle-2`。
- 普通浏览器只读模式可以正确显示和试玩已有冰冻关卡，但不能修改。
- WebView 文件桥写入仍沿用现有原子保存队列；任何文件写入失败都保留脏状态。
- 不修改现有 99 个清单关卡，也不自动把未入清单的 `level-101.json` 加入清单。
- 不改变普通物件、爆炸桶、固定螺栓、炮弹、平台或山体的既有规则。

## 验收标准

1. 可用编辑器把 1 个或多个相邻物件创建为冰冻体，保存、重开、导出和导入后关系不变。
2. 不相邻物件、重复归属、缺失成员或固定螺栓成员会被准确拒绝并标出具体对象。
3. 冰冻体总质量等于成员质量总和，并能在重力、炮弹和爆炸冲量下自然移动与旋转。
4. 前一次有效炮弹命中只产生裂纹；第二次有效命中释放全部成员。
5. 低于阈值的碰撞不扣耐久；同一次持续接触或同一爆炸不会重复扣耐久。
6. 冰冻阶段内部木材、玻璃和爆炸桶不受伤、不引爆；释放后恢复原规则。
7. 释放物件继承刚体线速度、角速度及旋转切向速度。
8. 单个物件、多个矩形、旋转物件、圆形和多边形组成的冰冻体均使用贴合轮廓的碰撞，不存在外包矩形空气墙。
9. 整体移动、旋转、复制、删除、解除、撤销和重做均保持分组一致。
10. 完整验证 `node scripts/verify.mjs` 通过，真实浏览器烟测控制台零错误，旧关卡与原玩法回归测试通过。

## 不在本次范围

- 可配置冰冻耐久。
- 不同冰层材质或多种冰冻视觉皮肤。
- 冰冻体之间自动合并。
- 运行中重新冻结已释放物件。
- 将冰冻体作为资源库中的独立可拖放物件。
