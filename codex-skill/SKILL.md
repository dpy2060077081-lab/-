# 图片差异审核工作流

项目必须包含 `原图/`、`修改图/`、`审核通过的成品/` 与 `.review/`。原图与已有修改版本始终只读，不覆盖、不删除。

## 导入这些原图

在仓库根目录执行：

```text
python import_images.py "<源目录>" "<项目数据目录>"
```

脚本递归导入 JPEG、PNG、WebP，按自然顺序编号，并用 SHA-256 去重。

## 生成下一组 / 生成 000127

读取目标编号文件夹内的原图。对每张尚无修改图的图片，使用当前会话的图片编辑能力生成差异化版本。保留主题、用途及美术风格大类；必要文字和 Logo 不交给模型重写。生成文件先写临时路径，完成后原子改名为 `修改图/<文件夹>/<图片编号>_v001.<扩展名>`。若目标名存在则停止，绝不覆盖。

“生成下一组”选择存在原图、但仍有图片没有任何合法修改版本的最小编号文件夹，每次最多十张。

### 生成提示词：主体替换限制

每张图片都必须将原图的主要视觉主体替换为一个明确不同且符合场景逻辑的新主体，并在提示词中写明原主体的画面功能以及模型自动选择的新主体。新主体应与原主体具有相近的用途、叙事角色、画面权重或类别关系，使图片继续保留原有主题和用途，例如将狗替换为猫、兔子替换为松鼠，或将主要食物、器物、建筑、植物替换为同用途且合理的另一种主体。仅改变颜色、品种、姿势、服装、表情、细节或拍摄角度不算完成主体替换；存在多个主体时，至少替换最主要的视觉焦点，其他元素可按场景合理调整。

主体替换默认保持主要主体的大类一致：原主体是人时，替换为身份、年龄、职业、造型或人物设定明确不同的另一个人；原主体是动物时，替换为场景合理的另一种动物。不要把人替换成动物，也不要把动物替换成人。器物、食物、建筑、植物等主体同样优先在各自大类内选择合理的新主体。只有用户明确要求跨大类替换时，才允许突破这一限制。

### 生成提示词：主体观感限制

除非原图本身明确属于恐怖、怪诞或猎奇题材，否则新主体必须自然、友好且视觉上可接受。人物和动物不得出现畸形肢体、错误数量的五官或肢体、异常融合、破损身体、诡异面孔、寄生感结构，或其他容易引发生理不适的形象。统一检查时必须检查主体的脸部、眼睛、嘴部、手脚、肢体连接和整体轮廓；出现明显怪异、畸形或不适感的候选图直接判定为不合格，并使用下一合法版本重做。

### 生成提示词：风格与色调限制

生成前判断原图的整体色调属于暖色、冷色或中性/冷暖混合，并在每张图片的提示词中明确要求保持原图的整体色调倾向、主色关系、饱和度与明暗氛围。允许改变主体、背景、构图、光影和细节，但不得让冷色调原图整体变成暖色调，也不得让暖色调原图整体变成冷色调；中性或混合色调应保持原有的冷暖平衡。

### 生成提示词：画布比例限制

生成前读取并记录每张原图的像素宽度、高度、横竖方向和精确宽高比，并在对应提示词中明确要求输出保持相同的画布宽高比与方向。最终图片的宽高比必须与原图严格一致，以整数交叉相乘验证 `输出宽度 × 原图高度 = 输出高度 × 原图宽度`；不得横竖互换，也不得通过非等比拉伸使画面变形。比例不一致的结果不得通过检查或写入目标目录，应重新生成，或在不裁切核心主体且不拉伸的前提下裁切到原图比例后再次验证。

宽高比检查必须读取原图和候选图的实际像素元数据并程序化计算，不能依靠肉眼判断或只相信生成提示词。只有交叉相乘等式严格成立的候选图才可进入写入步骤；在完成报告中记录原图尺寸、输出尺寸和验证结果。比例不一致时不得先写入正式版本再补查。

### 批次生成与统一检查

先完成同一编号文件夹内全部待处理原图的分析与提示词准备，再为每张图片分别发起生成调用，并尽可能整批并行执行。等待本批最多十张全部生成结束后，一次性统一检查主体是否已明确替换、主体大类是否一致、主体观感是否自然可接受，以及主题、用途、美术风格、整体色调、程序化画布宽高比、构图差异和文件完整性，通过后再统一写入目标目录。不要为了阶段性检查将一批图片人为拆成每两张或每四张等小批次；仅在工具并发限制、单张失败或超时时单独处理受影响的图片。

## 处理待重做 / 重做指定图片

读取 `.review/redo_queue.json`，结合其中的 `reason`、原图及失败的 `current_path` 调整生成策略。新文件版本号为当前最高版本加一，完整写入后再原子改名。不得直接修改 `review.db` 中的人工结论。

## 当前边界

此 Skill 是安全交接骨架；图片生成仍由 Codex 当前会话显式执行，不建立 API 队列，也不自动批量生成全部图片。
